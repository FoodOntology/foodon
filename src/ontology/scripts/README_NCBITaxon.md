# NCBITaxon Replacement Checker

`check_ncbitaxon_replacements.py` checks NCBITaxon term identifiers used in
FoodOn source files against the live NCBI Taxonomy API and reports any that
have been superseded by a new primary identifier.  It can also update the
source file in place with the replacements it finds.

## Background

NCBITaxon IDs are periodically retired and replaced as taxonomy is revised.
A term has been replaced when the old ID appears in the `secondary_tax_ids`
field of an NCBI API response — meaning that ID is now a deprecated alias
pointing to a different, current primary `tax_id`.

The `imports/ncbitaxon_import.owl` file is generated by the ODK build process
(via `make refresh-ncbitaxon`) using OntoFox to fetch a hierarchy of taxonomy
terms from `imports/ncbitaxon_ontofox.txt`.  Because that step makes a remote
call to `https://ontofox.hegroup.org/` and can be slow or unreliable, this
script provides a lightweight way to detect stale IDs between full rebuilds.

## Supported Input File Formats

The script auto-detects the file format from the file extension.

| Extension | Format | How IDs are extracted |
|-----------|--------|----------------------|
| `.owl` / `.ofn` | OWL ontology | Every occurrence of `NCBITaxon_<digits>` on any line |
| `.txt` | OntoFox input | Lines whose first token is a URL containing `NCBITaxon_<digits>`; comment lines (`#`) are skipped |
| `.tsv` | ROBOT template | `NCBITaxon:<digits>` values in column 0; header and directive rows are skipped automatically |

## Installation

No third-party packages are required.  The script uses only the Python standard
library (`urllib`, `json`, `re`, `argparse`).  Python 3.10 or later is needed
for the `str | None` type union syntax.

## Usage

```
python scripts/check_ncbitaxon_replacements.py [options] [input_file]
```

`input_file` defaults to `imports/ncbitaxon_import.owl` when omitted.

### Options

| Option | Description |
|--------|-------------|
| `--update` | Prompt to approve each replacement before writing it to the file |
| `--update-auto` | Apply all replacements to the file without prompting |
| `-i` / `--import` | After processing a non-OntoFox file, add any IDs (or their approved replacements) that are missing from `imports/ncbitaxon_ontofox.txt` |
| `--api-key KEY` | NCBI API key — raises the rate limit from ~3 to ~10 req/s |
| `--ids ID1,ID2,...` | Check only these specific numeric IDs instead of reading a file |
| `--batch-size N` | IDs per API request (default: 500; do not exceed 500 or HTTP 414 errors occur) |
| `--tsv` | Write results to stdout as tab-separated values instead of a human-readable table |
| `-v` / `--verbose` | Print per-batch progress details |

## Examples

```bash
# Check all IDs in the default OWL import (report only):
python scripts/check_ncbitaxon_replacements.py

# Check an OntoFox source list:
python scripts/check_ncbitaxon_replacements.py imports/ncbitaxon_ontofox.txt

# Check a ROBOT template:
python scripts/check_ncbitaxon_replacements.py ../templates/robot_seafood.tsv

# Check a ROBOT template and prompt to approve each update:
python scripts/check_ncbitaxon_replacements.py --update ../templates/robot_seafood.tsv

# Check an OntoFox file and apply all replacements automatically:
python scripts/check_ncbitaxon_replacements.py --update-auto imports/ncbitaxon_ontofox.txt

# Save results as TSV (progress messages still go to stderr):
python scripts/check_ncbitaxon_replacements.py --tsv > replacements.tsv

# Use an NCBI API key for faster queries:
python scripts/check_ncbitaxon_replacements.py --api-key YOUR_KEY_HERE

# Check specific IDs by number:
python scripts/check_ncbitaxon_replacements.py --ids 1913631,121025,492052

# Check a ROBOT template and insert any missing IDs into the OntoFox import list:
python scripts/check_ncbitaxon_replacements.py -i ../templates/robot_seafood.tsv

# Combine: update replacements interactively AND import missing IDs into ontofox:
python scripts/check_ncbitaxon_replacements.py --update -i ../templates/robot_seafood.tsv
```

All progress messages and prompts are written to **stderr**; report output
goes to **stdout**.  This means `--tsv > output.tsv` produces a clean file
while prompts remain visible on screen.

```

Found 4 replaced NCBITaxon ID(s):
======= ... =======

  --------------------   --------------------   --------------------------------------------------   ----
  NCBITaxon_6657         NCBITaxon_197562       http://purl.obolibrary.org/obo/NCBITaxon_197562     Pancrustacea
  NCBITaxon_48037        NCBITaxon_40921        http://purl.obolibrary.org/obo/NCBITaxon_40921      Anethum
  NCBITaxon_252557       NCBITaxon_102210       http://purl.obolibrary.org/obo/NCBITaxon_102210     Benincasa
  NCBITaxon_1913631      NCBITaxon_3049887      http://purl.obolibrary.org/obo/NCBITaxon_3049887    Colistium guentheri
```

The **New URI** column contains the full OBO PURL for the replacement term,
which can be pasted into a browser to verify the new entry before accepting it.

### TSV (`--tsv`)

```
old_id          new_id          old_uri                                         new_uri                                          new_name
NCBITaxon_6657  NCBITaxon_197562  http://purl.obolibrary.org/obo/NCBITaxon_6657  http://purl.obolibrary.org/obo/NCBITaxon_197562  Pancrustacea
```

Columns: `old_id`, `new_id`, `old_uri`, `new_uri`, `new_name`

## Interactive Update Mode (`--update`)

When `--update` is given without `auto`, the script prints each replacement
one at a time and waits for a decision:

```
[1/6]  NCBITaxon_33514  →  NCBITaxon_3360502  (Rostroraja eglanteria)
       http://purl.obolibrary.org/obo/NCBITaxon_3360502
  Update? [y/n/q] (n):
```

| Input | Effect |
|-------|--------|
| `y` | Approve this replacement |
| `n` (or Enter) | Skip this replacement |
| `q` | Stop prompting; apply whatever has been approved so far |

Prompts are read from the terminal (`/dev/tty`) so they work correctly even
when stdout is redirected to a file.

## How the File Is Updated

Each format is updated in a way that preserves its conventions:

### OWL / OFN

Every occurrence of `NCBITaxon_<old>` is replaced with `NCBITaxon_<new>`
throughout the file.

### OntoFox `.txt`

For each replaced URL line, a `# REPLACED NCBITaxon_<old> # <old label>`
comment is inserted on the line immediately above it (matching the existing
file convention), preserving the old taxon label from the trailing comment.
The URL is updated to the new ID, and its trailing name comment is updated to
the current scientific name returned by the NCBI API.

Before:
```
http://purl.obolibrary.org/obo/NCBITaxon_6657 # Pancrustacea
```

After:
```
# REPLACED NCBITaxon_6657 # Pancrustacea
http://purl.obolibrary.org/obo/NCBITaxon_197562 # Pancrustacea
```

### ROBOT template `.tsv`

`NCBITaxon:<old>` in column 0 is replaced with `NCBITaxon:<new>`.  Header
and directive rows are unaffected.

## Importing Missing IDs into OntoFox (`-i` / `--import`)

When `-i` is given for any input file that is not already the OntoFox file,
the script compares the set of NCBITaxon IDs found in the input file (using
approved replacements where applicable) against the IDs already listed in
`imports/ncbitaxon_ontofox.txt`.  Any IDs that are absent from the OntoFox
file are looked up via the NCBI API to obtain their current scientific names
and then inserted into the `[Low level source term URIs]` section, just before
the `[Top level source term URIs and target direct superclass URIs]` marker.

Inserted lines follow the same format as existing lines in that section:

```
# Added from robot_seafood.tsv
http://purl.obolibrary.org/obo/NCBITaxon_3051908 # Pennahia aneus
http://purl.obolibrary.org/obo/NCBITaxon_3353515 # Chirodactylus spectabilis
```

After inserting new terms you should run `make refresh-ncbitaxon` (via the ODK
Docker wrapper) to rebuild `imports/ncbitaxon_import.owl` with the added terms.

## NCBI API Notes

- The NCBI Datasets API endpoint used is:
  `GET https://api.ncbi.nlm.nih.gov/datasets/v2/taxonomy/taxon/{ids}/dataset_report`
- IDs are submitted as a comma-separated list in the URL path.
- Without an API key the rate limit is ~3 requests/second; with one it is
  ~10 requests/second.  An API key can be obtained at
  https://www.ncbi.nlm.nih.gov/account/
- Batches are capped at 500 IDs to stay within the server's URL length limit.
  The `--batch-size` option can lower this but should not exceed 500.
- HTTP 429 (rate limit) responses are retried automatically with exponential
  back-off.
