# NCBITaxon Manager

`ncbitaxon_manager.py` manages NCBITaxon term identifiers used in FoodOn source
files.  It can:

- **Detect replaced IDs** — query the NCBI Taxonomy API and report any IDs that
  have been superseded by a new primary identifier
- **Update source files** — rewrite stale IDs in place (interactively or
  automatically)
- **Look up taxa** — print a markdown comparison table for one or more IDs
- **Sync the OntoFox import list** — insert IDs from template files that are
  missing from `imports/ncbitaxon_ontofox.txt`
- **Check for import gaps** — report IDs present in the OntoFox request file
  but absent from the generated OWL import

## Background

NCBITaxon IDs are periodically retired and replaced as taxonomy is revised.
A term has been replaced when the old ID appears in the `secondary_tax_ids`
field of an NCBI API response — meaning that ID is now a deprecated alias
pointing to a different, current primary `tax_id`.

The `imports/ncbitaxon_import.owl` file is generated by the ODK build process
(via `make refresh-ncbitaxon`) using OntoFox to fetch a hierarchy of taxonomy
terms from `imports/ncbitaxon_ontofox.txt`.  Because that step makes a remote
call to `https://ontofox.hegroup.org/` and can be slow or unreliable, this
script provides a lightweight way to detect and fix stale IDs between full
rebuilds.

## Supported Input File Formats

The script auto-detects the file format from the file extension.

| Extension | Format | How IDs are extracted |
|-----------|--------|----------------------|
| `.owl` / `.ofn` | OWL ontology | Every occurrence of `NCBITaxon_<digits>` on any line |
| `.txt` | OntoFox input | Lines whose first token is a URL containing `NCBITaxon_<digits>`; comment lines (`#`) are skipped |
| `.tsv` | ROBOT template | `NCBITaxon:<digits>` values in column 0; header and directive rows are skipped automatically |

## Installation

No third-party packages are required.  The script uses only the Python standard
library (`urllib`, `json`, `re`, `argparse`, `pathlib`).  Python 3.10 or later
is needed for the `str | None` type union syntax.

## Usage

```
python scripts/ncbitaxon_manager.py [options] [input_file]
```

`input_file` defaults to `imports/ncbitaxon_import.owl` when omitted.

### Options

| Option | Description |
|--------|-------------|
| `-l IDs` / `--lookup IDs` | Look up comma-delimited taxon IDs and print a markdown comparison table, then exit. Cannot be combined with `--update`, `--update-auto`, or `-i` |
| `--update` | Prompt to approve each replacement before writing it to the file; a lookup table is shown for each candidate |
| `--update-auto` | Apply all replacements to the file without prompting |
| `-i` / `--import` | After processing a non-OntoFox file, insert any IDs (or their approved replacements) that are missing from `imports/ncbitaxon_ontofox.txt` |
| `--check-missing` | Report IDs present in `ncbitaxon_ontofox.txt` but absent from `ncbitaxon_import.owl`; runs instead of the normal replacement check |
| `--api-key KEY` | NCBI API key — raises the rate limit from ~3 to ~10 req/s |
| `--ids ID1,ID2,...` | Check only these specific numeric IDs instead of reading a file |
| `--batch-size N` | IDs per API request (default: 500; do not exceed 500 or HTTP 414 errors occur) |
| `--tsv` | Write replacement results to stdout as tab-separated values instead of a human-readable table |
| `-v` / `--verbose` | Print per-batch progress details |

## Examples

```bash
# Check all IDs in the default OWL import (report only):
python scripts/ncbitaxon_manager.py

# Check an OntoFox source list:
python scripts/ncbitaxon_manager.py imports/ncbitaxon_ontofox.txt

# Check a ROBOT template:
python scripts/ncbitaxon_manager.py ../templates/robot_seafood.tsv

# Check a ROBOT template and prompt to approve each update:
python scripts/ncbitaxon_manager.py --update ../templates/robot_seafood.tsv

# Check an OntoFox file and apply all replacements automatically:
python scripts/ncbitaxon_manager.py --update-auto imports/ncbitaxon_ontofox.txt

# Save replacement results as TSV (progress messages still go to stderr):
python scripts/ncbitaxon_manager.py --tsv > replacements.tsv

# Use an NCBI API key for faster queries:
python scripts/ncbitaxon_manager.py --api-key YOUR_KEY_HERE

# Check specific IDs by number:
python scripts/ncbitaxon_manager.py --ids 1913631,121025,492052

# Check a ROBOT template and insert any missing IDs into the OntoFox import list:
python scripts/ncbitaxon_manager.py -i ../templates/robot_seafood.tsv

# Combine: update replacements interactively AND sync missing IDs into ontofox:
python scripts/ncbitaxon_manager.py --update -i ../templates/robot_seafood.tsv

# Look up one or two taxon IDs and display a comparison table:
python scripts/ncbitaxon_manager.py -l 1913631 --api-key YOUR_KEY_HERE
python scripts/ncbitaxon_manager.py -l 1913631,3049887 --api-key YOUR_KEY_HERE

# Check for IDs missing from the generated OWL import:
python scripts/ncbitaxon_manager.py --check-missing
```

All progress messages and prompts are written to **stderr**; report output
goes to **stdout**.  This means `--tsv > output.tsv` produces a clean file
while prompts remain visible on screen.

columns resolve to the same taxonomy record.  The `taxon id` row shows the
current primary ID and `secondary tax ids` confirms the old ID is now an alias.

described; parentheses are added around the authority when not already present.
Classification rank rows use `[name](OBO_URI)` markdown hyperlinks.

## Interactive Update Mode (`--update`)

When `--update` is given, the script presents each replacement one at a time.
A lookup table comparing the old and new IDs is displayed first, followed by
the approval prompt:

```
[1/4]  NCBITaxon_1913631  →  NCBITaxon_3049887  (Colistium guentheri)

| Field              | NCBITaxon:1913631                  | NCBITaxon:3049887                  |
| ------------------ | ---------------------------------- | ---------------------------------- |
| taxon id           | 3049887                            | 3049887                            |
| rank               | SPECIES                            | SPECIES                            |
| scientific name    | Colistium guentheri (Hutton, 1873) | Colistium guentheri (Hutton, 1873) |
| secondary tax ids  | 1913631                            | 1913631                            |
| **classification** |                                    |                                    |
| ...                | ...                                | ...                                |

  Update? [y/n/q] (n):
```

| Input | Effect |
|-------|--------|
| `y` | Approve this replacement |
| `n` (or Enter) | Skip this replacement |
| `q` | Stop prompting; apply whatever has been approved so far |

Prompts are read from the terminal (`/dev/tty`) so they work correctly even
when stdout is redirected to a file.  The lookup table is shown when
`--api-key` is provided; without a key it is skipped with a brief notice.

## How the File Is Updated

Each format is updated in a way that preserves its conventions:

### OWL / OFN

Every occurrence of `NCBITaxon_<old>` is replaced with `NCBITaxon_<new>`
throughout the file.

### OntoFox `.txt`

For each replaced URL line, a `# REPLACED NCBITaxon_<old> # <old label>`
comment is inserted on the line immediately above it, preserving the old taxon
label from the trailing comment.  The URL is updated to the new ID and its
trailing name comment is updated to the current scientific name from the NCBI
API.

Before:
```
http://purl.obolibrary.org/obo/NCBITaxon_6657 # Pancrustacea
```

After:
```
# REPLACED NCBITaxon_6657 # Pancrustacea
http://purl.obolibrary.org/obo/NCBITaxon_197562 # Pancrustacea
```

### ROBOT template `.tsv`

`NCBITaxon:<old>` in column 0 is replaced with `NCBITaxon:<new>`.  Header
and directive rows are unaffected.

## Importing Missing IDs into OntoFox (`-i` / `--import`)

When `-i` is given for any input file that is not already the OntoFox file,
the script compares the NCBITaxon IDs found in the input file (using approved
replacements where applicable) against the IDs already listed in
`imports/ncbitaxon_ontofox.txt`.  Any IDs that are absent are looked up via
the NCBI API to obtain their current scientific names and then inserted into
the `[Low level source term URIs]` section, just before the
`[Top level source term URIs and target direct superclass URIs]` marker.

Inserted lines follow the same format as existing lines in that section:

```
# Added from robot_seafood.tsv
http://purl.obolibrary.org/obo/NCBITaxon_3051908 # Pennahia aneus
http://purl.obolibrary.org/obo/NCBITaxon_3353515 # Chirodactylus spectabilis
```

After inserting new terms you should run `make refresh-ncbitaxon` (via the ODK
Docker wrapper) to rebuild `imports/ncbitaxon_import.owl` with the added terms.

## Checking for Missing Imports (`--check-missing`)

`--check-missing` runs instead of the normal replacement-detection flow.  It
reads `imports/ncbitaxon_ontofox.txt` (the IDs requested from OntoFox) and
`imports/ncbitaxon_import.owl` (the IDs that were actually fetched and
included) and prints any IDs present in the request file but absent from the
generated OWL file.  These gaps typically indicate formatting errors in the
OntoFox file or terms that OntoFox silently dropped.

```bash
python scripts/ncbitaxon_manager.py --check-missing
```

Output is one bracketed ID per line:

```
Checking for missing ids in imports/ncbitaxon_import.owl
[3049887]
[64659]
...
```

## NCBI API Notes

- Two NCBI Datasets API endpoints are used:
  - **Replacement detection** (batch, paginated):
    `GET .../dataset_report?returned_content=METADATA&page_size=N&table_format=SUMMARY`
  - **Lookup table** (small queries, no pagination):
    `GET .../dataset_report?table_format=SUMMARY`
- IDs are submitted as a comma-separated list in the URL path.
- Without an API key the rate limit is ~3 requests/second; with one it is
  ~10 requests/second.  An API key can be obtained at
  https://www.ncbi.nlm.nih.gov/account/
- Batches are capped at 500 IDs to stay within the server's URL length limit.
  The `--batch-size` option can lower this but should not exceed 500.
- HTTP 429 (rate limit) responses are retried automatically with exponential
  back-off.
